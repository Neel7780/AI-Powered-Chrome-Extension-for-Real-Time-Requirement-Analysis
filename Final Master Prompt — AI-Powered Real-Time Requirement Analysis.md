# 5. STRUCTURED LLM OUTPUT

Never rely on arbitrary natural-language LLM output.

Use structured JSON.

A conceptual schema:

```json
{
  "analysis": {
    "ambiguities": [
      {
        "id": "AMB-001",
        "source_text": "overall profile strength",
        "reason": "The term is subjective and lacks measurable criteria.",
        "type": "SUBJECTIVE_TERM",
        "severity": "HIGH",
        "confidence": 0.94
      }
    ]
  },
  "clarifications": [
    {
      "id": "CQ-001",
      "ambiguity_id": "AMB-001",
      "question": "What factors should determine overall profile strength?",
      "priority": "HIGH",
      "suggested_options": [],
      "requires_stakeholder_answer": true
    }
  ]
}
```

Adapt this schema to the existing project rather than blindly replacing existing models.

Validate:

- required fields
- types
- IDs
- arrays
- enum values
- empty/null values

If parsing fails:

```text
LLM response
      ↓
validation
      ↓
repair/retry if safe
      ↓
fallback
```

The server must not crash.

# 7. CLARIFICATION QUESTION QUALITY

Questions must be:

- specific
- concise
- contextual
- non-repetitive
- actionable
- targeted toward resolving a specific ambiguity

Bad:

```text
Can you clarify?
```

Good:

```text
What factors should determine overall profile strength?
```

Better:

```text
Which factors should determine profile strength, and how should
each factor influence the candidate ranking?
```

Avoid asking questions whose answers are already present in the transcript.

Do not ask unnecessary questions.

# 14. QUALITY EVALUATION

Implement a transparent, deterministic evaluator.

Evaluate the actual requirements.

Suggested dimensions:

### Clarity

Does the requirement contain ambiguous language?

### Completeness

Does it specify sufficient information?

### Specificity

Does it define concrete behavior?

### Testability

### Consistency

Does it conflict with other requirements?

### Quantifiability

Does it contain measurable criteria where appropriate?

### Traceability

Can the requirement be traced to transcript evidence or stakeholder clarification?

# 15. QUALITY FORMULAS

Do not hard-code final scores.

Use transparent formulas.

For example:

```text
Metric Score =
(number of requirements satisfying metric)
/
(total applicable requirements)
× 100
```

Then:

```text
OQI =
weighted average of applicable quality dimensions
```

Use documented weights.

Do not manipulate the output to guarantee a desired number.

Scores must be allowed to become low.

Scores must be allowed to become high.
